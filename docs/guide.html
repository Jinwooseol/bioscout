BioScout
개요 설계 동작 방식 진행 상황 가이드

가이드

Windows PowerShell 기준입니다. 설치, 평가 실행, Claude Code에 MCP 서버 연결, GitHub에 올리기 순서입니다.

설치와 확인

  1. uv 설치

    Python 버전과 가상환경을 함께 관리합니다. 이미 있으면 건너뜁니다. 설치 후 터미널을 새로 엽니다.

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

  2. 프로젝트 폴더로 이동하고 Git 기록 복원 (처음 한 번)

    cd "$env:USERPROFILE\OneDrive\Desktop\Jinwoo\01_Development\Projects\bioscout"
powershell -ExecutionPolicy Bypass -File .\_git_setup\setup.ps1

    원격 전송으로는 .git 폴더를 쓸 수 없어, 커밋 기록을 번들 파일로 함께 보냈습니다. 스크립트가 기록을 복원하고, 같은 이유로 빠진 .mcp.json과 CI 설정을 되살린 뒤 _git_setup 폴더를 지웁니다. 마지막에 커밋 목록과 "Working tree is clean"이 보이면 끝입니다. 이후에는 git log --oneline으로 확인합니다.

  3. 의존성 설치

    uv sync

    Python 3.12가 없으면 uv가 알아서 받습니다.

  4. NCBI API 키 설정 (권장)

    키가 없어도 동작하지만 초당 3건으로 제한됩니다. 키가 있으면 10건까지 늘어나 평가 실행이 빨라집니다. NCBI 계정 설정의 API Key Management에서 발급합니다.

    Copy-Item .env.example .env
notepad .env

    NCBI_API_KEY와 NCBI_EMAIL을 채웁니다. .env는 Git에 올라가지 않습니다.

  5. 단위 테스트

    uv run pytest -q

    32 passed가 나오면 정상입니다. 네트워크와 API 키를 쓰지 않습니다.

  6. 실제 API 스모크 테스트

    uv run python scripts/smoke_live.py

    MCP 서버를 실제로 띄우고 도구 5개를 차례로 호출합니다. 다섯 줄 모두 PASS여야 합니다. 11/4 이 PC에서 다섯 도구 모두 통과했습니다.

평가 실행

변형 A(LLM 단독)와 B(단순 RAG)를 PubMedQA 100문항과 도메인 셋으로 비교합니다. Claude API를 부르므로 비용이 듭니다. 처음에는 10문항으로 비용과 오류를 확인한 뒤 전체를 돌립니다.

  1. Claude API 키 설정

    Claude Console에서 키를 발급해 .env의 ANTHROPIC_API_KEY에 넣습니다. 키가 없으면 실행이 바로 멈추고 안내 문구를 보여줍니다.

    notepad .env

  2. 데이터셋 점검 (무료)

    uv run bioscout-eval check-datasets

    데이터셋이 기대는 PMID가 모두 PubMed에 있는지, 핵심 포인트가 must-cite 밖의 PMID를 가리키지 않는지 확인합니다. missing=none이어야 합니다.

  3. 검색만 먼저 재기 (무료)

    uv run bioscout-eval retrieval

    LLM 없이 변형 B의 검색 단계만 돌려, PubMedQA 원 논문이 질문 그대로 검색한 상위 10건에 드는 비율을 봅니다. 11/4 측정값은 85/100입니다.

  4. 10문항 시험 실행

    uv run bioscout-eval run --variants A,B --limit 10

    데이터셋마다 앞 10문항씩, 변형 2개를 돌립니다. 진행 줄마다 인용 수, 가짜 PMID 수, 비용이 찍히고 끝나면 결과표가 나옵니다. 질의당 비용이 설계의 추정과 크게 다르면 전체 실행 전에 알려 주세요.

  5. 전체 실행

    uv run bioscout-eval run --variants A,B

    결과표는 evals/reports/<run_id>.md에 남습니다. 이 파일의 숫자만 진행 상황과 README에 옮겨 적습니다.

  6. 재채점과 재생

    uv run bioscout-eval report evals/runs/<run_id>
$env:BIOSCOUT_CACHE_MODE = "readonly"; uv run bioscout-eval run --variants A,B

    첫 줄은 기존 레코드로 결과표만 다시 만듭니다. 둘째 줄은 캐시된 응답만으로 같은 실행을 네트워크 없이 재현합니다. 끝나면 Remove-Item Env:BIOSCOUT_CACHE_MODE로 되돌립니다.

Claude Code에 연결

프로젝트 폴더에서 Claude Code를 열면 .mcp.json에 등록된 bioscout 서버를 쓸지 묻습니다. 승인하면 바로 쓸 수 있습니다. 다른 폴더에서도 쓰려면 사용자 범위로 추가합니다.

claude mcp add --scope user bioscout -- uv --directory "C:\Users\Jinwoo\OneDrive\Desktop\Jinwoo\01_Development\Projects\bioscout" run bioscout-mcp
claude mcp list

연결되면 이렇게 시험해 봅니다.

최근 5년간 cfDNA에서 digital PCR로 MSI를 검출한 논문을 찾아서,
핵심 결과를 문장마다 PMID를 달아 요약해줘. 인용한 PMID는 check_pmids로 확인해.

Claude Desktop에 연결

%APPDATA%\Claude\claude_desktop_config.json을 열어 아래를 넣고 Claude Desktop을 다시 시작합니다. JSON에서는 역슬래시를 두 번 씁니다.

{
  "mcpServers": {
    "bioscout": {
      "command": "uv",
      "args": [
        "--directory",
        "C:\\Users\\Jinwoo\\OneDrive\\Desktop\\Jinwoo\\01_Development\\Projects\\bioscout",
        "run",
        "bioscout-mcp"
      ]
    }
  }
}

GitHub에 올리기

로컬 저장소와 커밋은 준비되어 있고, 원격 저장소만 없습니다.

  1. 빈 저장소 만들기

    github.com/new에서 이름을 bioscout로 하고, 포트폴리오용이니 Public으로 만듭니다. README, .gitignore, License는 추가하지 않습니다. 이미 레포에 있습니다.

  2. 올리기

    git remote -v
git push -u origin main

    setup.ps1이 원격(origin)을 이미 등록했으므로 push만 하면 됩니다. 처음 push할 때 GitHub 로그인 창이 뜹니다. 올린 뒤 Actions 탭에서 CI(린트, 테스트, 서버 기동)가 초록색으로 끝나는지 확인합니다.

문제가 생기면

uv 명령을 찾을 수 없다

설치 직후에는 PATH가 반영되지 않습니다. 터미널을 새로 엽니다.

uv sync에서 Missing expected target directory for Python minor version link

uv가 Python 3.12를 받은 뒤 버전 링크를 만들지 못한 경우입니다. 11/4 이 PC에서 실제로 났습니다. 받아 둔 실행 파일을 직접 지정하면 됩니다.

uv python list --only-installed
uv sync --python "$env:APPDATA\uv\python\cpython-3.12.16-windows-x86_64-none\python.exe"

한 번 .venv가 만들어지면 이후 uv run은 그대로 동작합니다.

평가 실행이 ANTHROPIC_API_KEY is not set으로 멈춘다

.env에 키가 없습니다. 위 "평가 실행" 1단계를 봅니다. 이미 캐시된 실행을 재생만 하려면 BIOSCOUT_CACHE_MODE=readonly로 키 없이 돌릴 수 있습니다.

스모크 테스트에서 Source temporarily unreachable

네트워크나 방화벽 문제, 또는 NCBI 일시 장애입니다. 회사망이면 프록시를 확인하고, 잠시 후 다시 실행합니다. 같은 요청은 캐시되므로 다시 돌려도 API를 중복 호출하지 않습니다.

Replay mode: no recorded response

BIOSCOUT_CACHE_MODE=readonly로 설정되어 있습니다. 평소에는 .env에서 이 줄을 지우거나 readwrite로 둡니다.

git status에 모든 파일이 수정됨으로 보인다

줄바꿈 변환 설정 차이입니다. 저장소 안에서 아래를 실행합니다.

git config core.autocrlf false
git add --renormalize .
git status
OneDrive 동기화가 느려지거나 .venv 파일이 잠긴다

.venv에는 파일이 수천 개라 OneDrive가 계속 동기화합니다. 불편하면 저장소를 OneDrive 밖, 예를 들어 C:\Users\Jinwoo\dev\bioscout로 옮기고 그 경로로 Claude Code와 Claude Desktop 설정을 바꿉니다.

도구별 입력과 출력은 동작 방식에 있습니다.
