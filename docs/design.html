설계

1주 안에 "에이전트를 만들었다"가 아니라 "평가로 인용 정확도를 얼마나 올렸다"는 숫자를 남기는 것이 목표입니다. 그래서 평가셋과 baseline을 먼저 만들고, 기능은 하루에 하나씩 더하며 숫자로 효과를 확인합니다.

데이터 계약

에이전트는 자유 텍스트가 아니라 아래 구조로 답합니다. 문장 단위로 인용과 판정이 붙어 있어야 데모는 배지를 그리고, 평가 하네스는 지표를 계산할 수 있습니다. 평가 하네스가 먼저 필요해 Day 2에 src/bioscout/answer.py의 Pydantic 모델로 고정했습니다.

{
  "question": "MSI-H 대장암에서 PD-1 억제제 반응률은 MSS보다 높은가?",
  "decision": "yes",                   // yes | no | maybe | not_applicable (PubMedQA 채점용)
  "sentences": [
    {
      "text": "MSI-H 종양군의 객관적 반응률이 MSS군보다 높게 보고되었다.",
      "citations": ["10000002"],
      "verdict": "supported",          // supported | partial | unsupported
      "evidence": "초록에서 판정 근거가 된 문장"
    }
  ],
  "dropped": [ { "text": "...", "citations": ["10000003"], "reason": "pmid_not_found" } ],
  "searches": [ { "query": "\"microsatellite instability\"[MeSH] AND ...", "pmids": ["..."] } ],
  "usage": { "usd": 0.0, "latency_ms": 0, "tool_calls": 0, "model": "claude-opus-5-5" }

평가 설계

평가가 이 프로젝트의 본체입니다. 같은 평가셋, 같은 지표로 네 변형을 비교하고 그 결과표가 README와 LinkedIn 글의 헤드라인이 됩니다.

평가셋

셋규모구성재는 것
PubMedQA 서브셋100문항전문가 라벨 셋(PQA-L)에서 무작위 추출, 문항마다 원 논문 PMID 존재정답률, 원 논문 검색 성공률
도메인 셋25문항MSI · dPCR · liquid biopsy 질문 직접 작성, 문항마다 꼭 인용할 PMID와 핵심 포인트 2–4개핵심 포인트 커버리지, must-cite recall
판정 보정셋60쌍에이전트 출력의 (문장, 인용 초록) 쌍을 직접 라벨링LLM judge와 사람 판정의 일치도
범위 밖 질문10문항개인 치료 결정 요청 등연구 탐색 범위로 안내하는지

지표

지표정의판정 방식
가짜 PMID 비율인용한 PMID 중 PubMed에 없는 비율check_pmids, 결정적
Citation precision인용 중 해당 문장을 실제로 지지하는 비율LLM judge, 보정셋으로 검증
Citation coverage사실 진술 문장 중 지지 인용이 1개 이상인 비율LLM judge
정답률 · 키포인트 커버리지PubMedQA 라벨 일치, 도메인 셋 핵심 포인트 포함 비율규칙 + LLM judge
Retrieval recall@10정답 PMID가 검색 상위 10건에 들어간 비율결정적
비용 · 지연질의당 USD, p50/p95 지연, 도구 호출 수트레이스 집계

비교 변형

변형구성보여주는 것
A. LLM 단독도구 없이 답변 + PMID 인용 요청인용 환각이 실제로 얼마나 일어나는가
B. 단순 RAG질문 그대로 PubMed 상위 10건 초록 → 답변일반적인 RAG의 한계
C. 에이전트질문 분해, 검색어 재작성, 다중 도구에이전트 설계의 효과
D. 에이전트 + 검증C + 인용 검증 · 재검색 루프검증 루프의 효과와 그 비용

PubMedQA 질문은 논문 제목에서 만들어져 검색 성공률이 낙관적으로 나오고, 모델이 학습 중 봤을 가능성도 있습니다. 그래서 직접 만든 도메인 셋 결과를 항상 함께 제시합니다.

평가 하네스 (Day 2)

평가 하네스는 "문항 × 변형"마다 답변을 하나 받아, 사람 손을 거치지 않는 결정적 지표부터 채점합니다. 판정이 필요한 지표(citation precision, coverage)는 judge를 보정한 뒤 Day 4에 같은 레코드 위에 더합니다. 그래서 Day 2 레코드는 나중에 다시 실행하지 않고 재채점할 수 있게 원자료를 모두 남깁니다.

파일 구성

위치내용Git
src/bioscout/answer.py답변 데이터 계약(CitedAnswer). 변형, 데모, 채점이 모두 이 모델을 씀커밋
src/bioscout/llm.pyClaude 호출 래퍼: JSON 스키마 출력, refusal fallback, 토큰 비용 계산, 응답 캐시커밋
src/bioscout/evals/datasets 로딩, variants(A, B), metrics, runner, cli커밋
evals/datasets/문항 JSONL. PMID, 질문, 라벨, 우리가 쓴 핵심 포인트만. 초록·본문 없음커밋
evals/runs/<run_id>/records.jsonl(문항별 답변과 채점), meta.json(모델, effort, 프롬프트 해시)제외
evals/reports/<run_id>.json, .md변형별 요약 수치와 결과표커밋

실행 명령은 uv run bioscout-eval run --variants A,B --datasets pubmedqa,domain입니다. --limit 10으로 먼저 10문항만 돌려 비용과 오류를 확인한 뒤 전체를 돌립니다.

레코드 형식

// evals/datasets/pubmedqa_100.jsonl (한 줄 = 한 문항)
{"id": "pqa-10000001", "dataset": "pubmedqa", "question": "...", "answer": "yes", "pmid": "10000001"}

// evals/datasets/domain.jsonl
{"id": "dom-msi-01", "topic": "msi", "question": "...", "must_cite": ["10000002"],
 "key_points": [{"point": "...", "pmids": ["10000002"]}], "status": "draft"}

// evals/runs/<run_id>/records.jsonl (한 줄 = 문항 × 변형)
{"item_id": "pqa-10000001", "dataset": "pubmedqa", "variant": "B",
 "answer": { CitedAnswer },
 "scores": {"cited": 4, "fabricated": 0, "sentences": 3, "cited_sentences": 3,
            "correct": true, "retrieved_gold": true, "gold_cited": true},
 "error": null}

예시의 PMID는 가상 번호입니다. 실제처럼 보이는 가짜 인용은 테스트 픽스처 밖에 두지 않습니다.

Citation precision, coverage, 핵심 포인트 커버리지는 LLM judge가 필요해 Day 4에 보정셋으로 judge를 검증한 뒤 같은 레코드에 더합니다.

항목값이유

effortmedium (BIOSCOUT_EFFORT)모델 기본값과 같지만 실행 기록에 남도록 명시

기술 결정

결정이유버린 대안
MCP SDK 2.x의 MCPServer 사용현재 SDK 기준. 1.x의 FastMCP가 2.x에서 이름이 바뀌었으므로 처음부터 2.x로 작성mcp<2 고정
검색 엔진은 PubMed API 자체3,700만 건 인덱싱 없이 1주 안에 가능하고, 관련도 정렬 품질이 충분. 대신 검색어 재작성을 에이전트의 일로 둠자체 벡터DB 인덱싱
SQLite 응답 캐시 + readonly 모드NCBI 속도 제한 준수, 평가 재현성, CI에서 네트워크 없이 재생매번 실시간 호출
업스트림 오류를 짧은 도구 오류로 변환에이전트가 스택 트레이스 대신 "재시도하거나 다른 도구 사용"을 읽고 행동예외 그대로 전달
테스트 픽스처는 가상 데이터인용 진실성을 다루는 프로젝트에서 실제처럼 보이는 가짜 인용을 만들지 않음실제 응답 녹화본 커밋
평가 하네스 직접 작성지표 정의를 면접에서 직접 설명할 수 있어야 함. RAGAS는 참고 지표로만RAGAS 단독
모든 변형에 같은 모델 · effort · 출력 스키마변형 간 차이를 모델이 아니라 설계(검색, 에이전트, 검증)에서 온 것으로 해석하기 위해변형마다 최적 모델
LLM 응답도 SQLite에 캐시재채점과 CI 재생에 API 비용이 들지 않음. 새 표본이 필요하면 캐시를 끄고 실행매번 새로 호출
Claude 호출에 fallbacks: "default"안전 분류기가 생의학 질문을 오탐해 거절하면 문항이 통째로 빠짐. 대신 응답한 모델을 기록해 결과에 표시거절을 오답으로 처리
PubMedQA는 PMID · 질문 · 라벨만 저장원본 JSON의 초록(CONTEXTS)과 결론(LONG_ANSWER)은 저장하지 않음. 고정 시드로 재추출 가능원본 파일 커밋

범위 밖

  • 자체 벡터DB 대규모 인덱싱, 모델 파인튜닝
  • 전문(full text) 대량 저장·재배포. 초록과 오픈액세스 본문만 실시간 조회
  • 임상 의사결정 지원. Intended use는 "연구 문헌 탐색 보조"
