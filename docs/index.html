BioScout는 바이오메디컬 질문에 답할 때 문장마다 PubMed 논문(PMID)을 붙이고, 그 논문이 실제로 문장을 뒷받침하는지 판정한 뒤에야 답변을 보여주는 리서치 에이전트입니다.

질문: MSI-H 대장암에서 PD-1 억제제 반응률은 MSS보다 높은가?
  1. MSI-H는 DNA 불일치 복구(MMR) 결함으로 생긴다. PMID 10000002
  2. MSI-H 종양군의 객관적 반응률이 MSS군보다 높게 보고되었다. PMID 10000002
  3. 이 차이는 cfDNA 기반 MSI 검출로도 재현된다. PMID 10000001 초록은 검출 방법만 다루고 반응률은 다루지 않아 부분 지지로 표시
  4. 반응은 모든 환자에서 2년 이상 지속된다. PMID 10000003 PubMed에 없는 PMID라 근거가 없고, 고쳐 쓸 내용도 초록에 없어 답변에서 삭제

출력 형식을 보여주는 예시입니다. PMID와 문장은 가상이며 실제 논문을 가리키지 않습니다.

왜 필요한가

LLM에게 바이오메디컬 질문을 하면 그럴듯한 인용이 붙어 나옵니다. 그 인용이 맞는지는 읽는 사람이 논문을 열어 직접 확인해야 합니다. 공개된 측정 결과가 이 문제의 크기를 보여 줍니다.

모델이 좋아질수록 "없는 논문"은 줄고, "실제로 있지만 그 문장을 뒷받침하지 않는 논문"이 남습니다. 이런 인용은 논문이 존재하는지만 확인해서는 걸러지지 않습니다. 문장과 초록을 맞대어 봐야 합니다. BioScout는 그 확인을 사람에게 넘기지 않고, 답변을 보여 주기 전에 하도록 설계했습니다.

비슷한 도구가 이미 있는가

있습니다. 논문 근거를 달아 답하는 서비스는 이미 여럿이고, 대부분 BioScout보다 크고 완성도가 높습니다.

BioScout는 이 서비스들을 대체하려는 제품이 아닙니다. 차이는 기능의 수가 아니라 공개 범위에 있습니다. 상업 서비스는 검색과 판정 과정, 평가 데이터를 공개하지 않습니다. 그래서 인용이 얼마나 정확한지를 밖에서 다시 재 볼 수 없고, 회사가 발표한 수치를 믿어야 합니다. BioScout는 검색 방식, 프롬프트, 평가셋, 채점 코드, 결과 리포트가 모두 저장소에 있어 누구나 같은 숫자를 다시 만들 수 있습니다. 가장 가까운 오픈소스인 PaperQA2는 논문 전문을 다루는 더 큰 시스템이고, BioScout는 PubMed 초록과 PMID 단위 검증으로 범위를 좁힌 작은 구현입니다.

일반 AI 에이전트 대신 쓰면 얻는 것

범용 에이전트도 검색하고 출처를 답니다. BioScout가 다른 점은 네 가지입니다.

이점내용상태
인용을 시스템이 검사답변의 모든 PMID를 PubMed에 조회해 존재를 확인합니다. 이어서 문장과 초록을 맞대어 지지, 부분 지지, 근거 없음으로 판정합니다. 부족한 문장은 초록에 있는 내용으로 한 번 고쳐 쓰고, 그래도 근거가 없으면 삭제합니다구현됨 검증 변형 평가 전
PubMed를 직접 검색웹 페이지가 아니라 NCBI의 PubMed를 PMID 단위로 조회합니다. 질문을 MeSH 용어와 동의어 검색식으로 바꾸고, 초록을 읽어 근거가 되는 논문만 골라 답변에 씁니다구현됨
성능이 숫자로 공개됨같은 모델로 LLM 단독, 단순 RAG, 에이전트, 에이전트 + 검증을 비교합니다. 가짜 PMID 비율, 인용 정확도, 질의당 비용과 시간이 리포트로 남고, 응답 캐시로 같은 실행을 다시 재생할 수 있습니다A–D 구현됨 D 평가 전
도구를 떼어 쓸 수 있음PubMed 검색, 초록, PMID 확인, 오픈액세스 본문, 임상시험 검색을 MCP 서버로 제공합니다. Claude Code나 Claude Desktop 같은 MCP 지원 에이전트에 그대로 연결됩니다. 공개 API만 써서 구독료가 없고, 드는 비용은 LLM 호출뿐입니다구현됨

근거로 확인된 문장은 답변 문장 중 인용한 초록이 그 내용을 모두 뒷받침한 비율(citation coverage)입니다. 인용 정확도는 인용 중 초록이 문장을 분명히 뒷받침한 비율(citation precision)입니다. 둘 다 judge가 판정했습니다.

  • LLM 단독의 답변 115개 중 98개는 근거로 확인된 문장이 하나도 없습니다. 대부분의 문장에 인용을 달지 않았고, 기억으로 단 인용도 절반만 문장을 뒷받침했습니다. 인용의 11%는 초록이 문장을 전혀 뒷받침하지 않았습니다. 항응고제 임상시험을 말하는 문장에 청소년 치과 진료 연구가 달린 식으로, 실제로 있지만 전혀 다른 논문을 가리킨 경우가 여럿입니다.
  • 단순 RAG는 논문을 찾았을 때는 정확합니다. 하지만 답변 24개에는 확인된 문장이 하나도 없습니다. 도메인 질문 15개 중 13개에서 검색 결과가 0건이었습니다. 긴 질문은 PubMed가 모든 단어를 AND로 묶기 때문입니다.
  • 에이전트는 모든 답변에 확인된 문장이 있고, 답변 80개는 모든 문장이 확인됐습니다. 문장과 무관한 논문을 인용한 경우는 0.7%입니다. 인용 정확도가 단순 RAG보다 낮은 것은 원 논문 말고도 여러 논문을 인용하기 때문입니다. 어긋난 인용은 대부분 주제는 맞지만 문장의 세부까지는 말하지 않는 부분 지지입니다. 비용은 약 6배이고 질의당 20초가 걸립니다.
  • 이 수치는 아직 잠정입니다. judge의 판정이 사람의 판정과 얼마나 맞는지 60쌍으로 확인하는 일이 남아 있습니다.

수치는 evals/reports/20261115-195946-ABC에서 옮겼습니다. PubMedQA 100문항과 도메인 15문항이며, 도메인 수치는 문항이 적어 방향만 보여 줍니다.

문헌 근거를 문장 단위로 확인해야 하는 연구자, 그리고 인용을 다는 LLM 에이전트를 만들고 평가하려는 개발자에게 쓸모가 있습니다.

한계

  • 초록만 읽습니다. 본문에만 있는 근거는 찾지도 판정하지도 못합니다.
  • 인용 정확도 수치는 잠정입니다. judge가 답변과 같은 모델이고, 사람 라벨과 맞는지 확인하는 일이 남아 있습니다.
  • 근거 없는 문장을 고쳐 쓰거나 빼는 단계는 만들었지만 아직 평가하지 않았습니다. 공개 주소의 데모는 기록된 예시 답변 3개만 보여 줍니다. 직접 질문하려면 자기 API 키로 로컬에서 실행해야 합니다.
  • 혼자 만드는 포트폴리오 프로젝트입니다. 상업 서비스 수준의 규모, 속도, 지원은 없습니다.
  • 의료기기가 아닙니다. 개별 환자의 진단이나 치료 결정에 쓰지 않습니다.

다른 도구의 설명은 2026년 11월에 각 사 공개 자료를 확인한 내용입니다. 기능은 바뀔 수 있으니 각 사이트에서 확인하세요.

  • 진행 상황

    설치, 테스트, 평가 실행, Claude Code와 Claude Desktop 연결, GitHub 푸시
